# Aether architecture

Aether is an Electron desktop app. It has a main process that can call providers and access OS APIs, and a renderer process that draws the floating panel and captures browser media tracks. `preload.js` exposes a narrow IPC bridge between them.

Zen capture accepts viewport changes, including fullscreen, before a new screenshot. It checks geometry again after capture and before input so stale coordinates remain blocked. Keypad fill reuses a preceding focus click on the same field to avoid toggling its keypad closed.

For native HTML dropdowns, Zen select/focus clicks read enabled option labels using a fixed hit-test script instead of opening the browser-level popup. The model selects an exact label through a click's optional `option`; WebDriver ElementClick acts on the unique enabled option, preserving native form events. The script traverses frames/open shadow roots, rejects disabled/multiple selects and ambiguous labels, and resets frame context. Custom page menus still use pointer input. Desktop mode rejects exact-option requests.

## Main files

Cycling answer galleries use click intent `cycle`. Optional `steps` (1–12) plus a bounded `region` collect successive choice screenshots locally without a model call between clicks. Every input still requires a fresh capture; unchanged pixels end the batch, and geometry changes or cancellation stop it. `src/choice-sheet.js` appends historical diagram crops below the unscaled current screenshot using Electron nativeImage, so existing single-image providers can compare the options together without changing action coordinates. `auto-session.js` supplies tile order/count and steps taken; a further bounded cycle can return to the chosen option. This relies on a stationary control and prompt-guided model recognition; it does not prove semantic progress from pixel changes.

## A typed factual question

Auto mode is a separate explicit task loop from Auto refresh. Main snapshots the selected provider, installs Escape, waits three seconds for target focus, then locks that exact native Hyprland window and geometry. Each model response must match a strict action schema. Every input consumes a screenshot authorization and checks target focus; typing requires a matching field-focus click. Source-based text references stable session evidence IDs. No shell or arbitrary key actions are exposed. Typing supports printable ASCII appended into empty fields; common math symbols are converted (π to pi). Consecutive typing in one field keeps focus. Math editors with a symbol palette use click intent `insert`, or one `type` whose `symbols` map gives each palette button so the engine types and clicks in text order. The same `symbols` map with ASCII keys drives click-only on-screen keypads (digits, '.'): the engine presses each button in order, repeats included, so a whole value costs one model step; a `fill` action enters up to 10 fields from one decision (focus click + value each), and every extra input inside one action takes a fresh capture first because executors accept one input per screenshot; pressed keypad/palette points are kept as `knownButtons` (dropped on scroll) and sent back each turn, and a field's optional `clearButton` is pressed after its focus click so re-entry never appends; after a type/fill the observation names every value entered so the model checks the boxes digit by digit; in Zen tabs keypad button positions (and Clear) come from the page via `zen-control.findButtons`/`pickButtons` instead of the model's pixel guesses; every run is logged to `<userData>/auto-runs/` by `src/run-log.js` (trace.jsonl + changed screenshots, newest 5 kept) for replaying failures into tests, and the engine pauses after `stallSteps` (15) steps with no real progress; an optional `work` field carries arithmetic before the answer. After Next/Submit the engine waits up to 15 s on unchanged or blank frames (`isBlankFrame`, zlib PNG row bands) before asking the model, and refuses a second Submit with no answer change in between. `clear` (fixed Ctrl+A, Backspace) erases the field just focused, so wrong or prefilled values can be retyped. The UI is the direction-3 instrument design (renderer/index.html, styles.css). A separate dock window (renderer/dock.*, dock-preload.js, created in main.js `createDock`) sits top-center under the bar; clicking it opens the panel under it (`openPanelFromDock`, Hyprland placement via `hyprPlace` in src/linux-overlay.js), swiping it up dismisses it. The panel is pinned (follows workspaces) except during desktop Auto, when `setPanelPinned(false)` in main.js keeps it on the run's workspace until `onEnd` re-pins it. To add a dock state, extend `paint()` in renderer/dock.js and pass the data through `updateDock()` in main.js; new panel controls go in renderer/index.html using the existing key/slide/switch classes in styles.css. In Zen tab mode a second cursor (`CURSOR_SCRIPT` in `src/zen-control.js`) draws a purple Aether arrow at each click, drag and scroll point, with a ripple on clicks. It is `pointer-events:none`, hidden during screenshots so the model never sees it, failures never block input, and `release()` removes it when the run ends. Submission defaults to user review. An unchecked renderer control enables form submission for one run, passed as a trusted boolean through preload, main and session; the model cannot grant itself permission.

The model can return a map action describing form layout, current question, navigation meaning, unread scroll direction, and answer/completion state. The engine retains the map independently of its short action history. Input clears answer verification; Next/Submit clears the map. Submission requires a verified answer with no unread content or pending field input, and completion after submission requires a fresh confirmation map. Exact screenshot equality produces feedback about unchanged pixels, which can also occur after a harmless focus click or at a scroll boundary. Malformed actions receive two bounded correction opportunities. This remains screenshot-driven: model map fields and labels are claims, not DOM-derived guarantees. Vector/FBD questions use a `vector` action: the model gives label, magnitude, angle, origin and one axis tick; the engine computes pixels, converts it to a drag, and corrects from the tool's readout plus the observed arrowhead (3 corrections per label). Other graphing questions (curves, plotted points, shading) are never attempted: the model returns `skip` with the question and exact manual steps, which unlocks one Next click; every skipped question is appended to the final status message, surviving Escape and errors. See [form automation research](docs/form-automation.md).

Click/type/scroll/drag/done responses can also include a strict `form` object describing the current screenshot, reducing separate mapping requests. The repetition guard compares consecutive screen images, permits identical Next clicks when pixels change, blocks duplicate same-point selection input, and gives recovery guidance before pausing with action type/intent. Pixel changes are not semantic proof of page progress. Desktop mode still shares focus and pointer; Zen tab mode provides separate browser input.

Drag carries bounded screenshot start/end coordinates and moves one answer before taking another screenshot. Both points must be visible; input invalidates answer verification before submission. Zen converts coordinates by DPR, then uses a held native pointer for custom mouse/pointer widgets. Hidden Gecko tabs start HTML native drags without completing drop, so explicit HTML draggable elements instead use a fixed DragEvent/DataTransfer adapter, with bounded iframe traversal and top-context cleanup. Those HTML events are synthetic and cannot satisfy a site that requires trusted HTML drag events. Hidden tabs also omit hover transitions, so before release Zen dispatches one fixed `mouseover` at the destination and then nudges the held pointer 1px and back; legacy libraries such as YUI 3 DD only register the drop target on the move after hover. No model-provided script is accepted. Desktop drag uses Hyprland cursor motion and ydotool button hold/release, checking focus/overlay positions between moves and cleaning up on interruption.

A failed research lookup (for example no Tavily key) becomes feedback and the run continues from the model's own knowledge. The engine watches for stalls: an unchanged screen after a select or Submit click gets targeted feedback, a repeated map of an unchanged screen gets a nudge, and three in a row pause the run. Next/Submit waits 1s before the next screenshot. Click accepts optional clicks:2 (select intent only) for pages that need a double click, such as Amplifire's "sure" mark; Zen sends two press/release pairs and desktop mode uses ydotool --repeat 2. Screenshots may come back at device pixels or at 1x CSS pixels; capture detects which and coordinates follow that scale. Zen tab mode now supplies a separate controller to the same Auto session/engine. Connect opens a bounded Marionette session at 127.0.0.1:2828 and lists existing web tabs; the user selects an exact handle. Each capture/action reselects it with `focus:false` and validates its viewport. PNG coordinates are converted to CSS coordinates using DPR, including fractional canvas-size truncation. No arbitrary model evaluation, browser Quit/DeleteSession or user-tab-close action is exposed. Initial connection may activate Zen once; subsequent hidden-tab input passed OS focus/cursor isolation checks on this host. Tab handles must be refreshed after reconnecting.

Auto target uses in-page Desktop/Zen radio controls; connected tabs appear as an inline radio list. Native popup selection failed in the live overlay, so selector checks must click these controls rather than assign their values programmatically. Fieldsets disable both groups during a running task.

Zen's `focusmanager.testmode` preference enables background element focus, which native typing requires. Clicks and paired key actions are browser-native; hidden-tab wheel behavior was unreliable, so scrolling uses a fixed bounded hit-test/ancestor-scroll script with iframe traversal and top-frame reset. Cancellation drains submitted actions and releases pressed input before another task can start. Zen tasks can continue while the overlay is hidden; renderer destruction/reload, app quit and Escape/Stop still cancel. The same provider/account and form-submission permission rules apply. See [Zen setup](docs/zen-tab-control.md).

Cancellation aborts model/helper work and waits for in-flight native input to close. The executor first checks ydotool daemon connectivity without emitting input, then rechecks focus. Failed/interrupted ydotool input releases virtual keys and buttons on the same device before another task can start. Short typing chunks recheck focus, but native focus checks and input are not atomic. Runs stop after 80 decisions or ten minutes. Auto uses only the explicit goal, screenshots and retrieved evidence, without injecting the saved résumé. Each screenshot goes to the selected provider.

1. The renderer sends the question and mode through the preload bridge.
2. `main.js` captures a screenshot for **Ask**, or skips it for **Research**.
3. `src/research.js` asks `src/library.js` for a local title match with the same normalized topic terms and enough source text. More specific titles do not satisfy a general-topic query. Current questions and misses use Tavily; if the model says local evidence is insufficient, it retries once with Tavily. No usable evidence produces an error.
4. The selected provider receives the question and numbered source passages, followed by instructions to preserve factual relationships, distinguish dates/events, and cite factual sentences. For factual modes, Aether waits for a complete draft and checks that its citation numbers refer to retrieved sources before displaying it. This check cannot establish semantic accuracy; live models have still changed facts. Ollama requests have a two-minute timeout so a stalled local model does not hold the UI indefinitely.
5. The renderer displays the answer and clickable source links. Library links credit Wikipedia contributors and CC BY-SA 4.0.

## Write mode

Write mode (the WRITE key on the panel) is a separate pipeline from Auto: Aether drafts from a prompt (or takes pasted text), humanises it with the InkSplash Config C subprocess, runs the detector (local AI% + fact score, optional ZeroGPT), and shows an editable review with the AI percentage and pass/fail. When the user approves, **the model is disengaged** (`write-session.approve()` drops the llm and stops the warm codex-server) and nothing after that calls a provider. The approved text is turned into a human-paced keystroke plan (`typing-plan.js`) and typed into a user-chosen Zen tab through `zen-control.writeKey`, which keeps going across desktop switches because it never uses the OS cursor. Escape/Stop, reload, close and quit cancel it. Typing knobs, the humaniser toggle, detector choice and the Python/humaniser paths live in Settings → Write mode; defaults model a slower, less-skilled typist. To extend: new typing behaviour goes in `typing-plan.js` (pure, unit-tested); new review/detector fields flow through `write-session.js`'s injected ports and the `write-mode:*` IPC.

## Links, quotes, and the humaniser

When a prompt contains links, `research.openLinks` fetches them (HTML to plain text) and that page text becomes the evidence instead of a web search. Links that fail are reported to the user by name and reason, and the model is told not to guess them. After the model answers, `research.verifyQuotes` checks every quotation of four or more words against the fetched text; anything not found word-for-word is flagged (a warning line in Ask/Research, amber notes on the Write review). In Write mode the user's prompt is the spec: the system prompt adds no voice of its own, and the model writes `[could not verify: …]` or `[could not open: …]` instead of inventing a quote or link.

Write mode shows the finished text first. The Humanize button runs rounds (`write-session.humanizeLoop`): the answer model (Codex) rewrites the best version so far with `createModelHumanizer` (`src/humanize.js`), and the detector scores it against the text as it was when Humanize was clicked, for AI %, meaning (MiniLM) and facts. Rounds that change a quote or drift are discarded. It stops under 20% AI or after 10 rounds. The local Config C pipeline is still selectable in Settings.

The humaniser never edits quotations. `humanize_cli.py` swaps each quoted span for a `[[Qn: words]]` marker before any engine runs and swaps the original back by number at the end. Every rewrite pass in `stealth_humanizer.py` rejects output that lost a marker; if the final text lost one anyway, the CLI exits 5 and the original text is kept. MiniLM meaning checks (sentence ≥ 0.80, whole text ≥ 0.85) drop rewrites that drift. A missing Ollama model is an error, never a silent pass-through. To extend: new quote formats go in `_QUOTE_RE` (Python) and `findQuotes` (JS); new link types go in `fetchPage`.

## Keyboard shortcuts
Smart controls response depth as well as the model tier. Answer mode (`false`) uses Fast and requests only the answer/code; Work (`true`) uses Smart and requests brief supporting work/evidence; Deep (`'deep'`) uses Smart and requests a worked answer with an in-depth explanation. One click toggles Answer/Work, double-click or Alt+Enter selects Deep. `responseSystem()` appends the shared depth/evidence policy to each task before résumé context. All factual levels retain required citations/uncertainty, and meeting modes keep their specific formats.

The renderer retains raw token text without trimming and batches formatting to animation frames. Both partial and finished output run through the same Marked/KaTeX parser and DOMPurify sanitizer. Code bypasses math parsing; model HTML is sanitized and remote images are omitted. Partial Markdown can settle as closing syntax arrives. Model-generated missing spaces cannot safely be guessed; transport and rendering preserve the supplied text.

Screen updates are manual by default. Native Hyprland users may enable click/scroll Auto refresh in Settings. External activity settles for 650 ms before Assist, and only the latest pending interaction survives a busy generation. Its display coordinates travel with the request. Main process visibility and renderer settings/onboarding/collapse state pause requests. Listener failure disables runtime Auto and reports an error; saved preference and actual running state are separate. Bindings are removed on disable/quit, without removing the user's mouse bindings; a compositor config reload requires restarting Aether.

Manual screen capture uses the cursor display; automatic capture uses the triggering interaction's display. Hyprland requires `grim` on PATH, reads PNG output as binary and fails closed with setup guidance. Other platforms use Electron's nearest display and portal source where available. Explicit screen questions bypass factual retrieval and stream tokens with progress labels; factual questions retain buffered citation validation. A visible overlay may be included in a screenshot. Model latency and semantic accuracy remain separate limits.


Settings reuses one key recorder for Assist and Show / hide. Preload sends each change to the main process, which checks conflicts, replaces the global binding, and persists the preference. A failed save restores the previous binding. The default restore combination is Ctrl+Shift+Space (Command+Shift+Space on macOS); labels follow saved settings. Startup registration status disables the sharing Hide button if no restore binding registered. This cannot prove Wayland will deliver keys; test physically before sharing. Linux packaging synchronizes `dev.prahladv.aether.desktop` with Electron's portal identity.

Electron 44 fixes host app registration with modern Wayland portals. `scripts/install-linux.js` installs the matching per-user desktop launcher for a built AppImage. `src/hypr-shortcut.js` connects the Show / hide portal action to a Hyprland Lua runtime binding. It waits for the portal action, rejects existing desktop key conflicts, replaces only Aether-owned bindings, and cleans up on quit. Main-process changes are serialized and roll back both native binding and Electron registration on failure. Restart Aether after a Hyprland configuration reload. This helper handles Show / hide; other global actions may still need desktop setup. Electron 44 raises the macOS minimum to 13.

## Listening

The renderer asks for a microphone track. On Linux, meeting audio comes from `parec` in the main process, capturing the default PulseAudio/PipeWire output monitor as 16 kHz, mono, signed 16-bit PCM. Other platforms keep the renderer's display-media path. Capture becomes active only after a usable track or native PCM arrives; the renderer rechecks availability after pending permission requests and activation. IPC carries native readiness and unexpected-end events, while an idempotent capture-stop operation keeps overlapping cleanup from toggling capture back on. The helper stops on cancellation, renderer reload/crash, window closure, or app quit, with a bounded startup wait and forced-stop fallback.

Audio is buffered in `main.js` by speaker channel. `src/stt.js` transcribes non-silent chunks. Local mode writes a private temporary WAV for `whisper-cli` and removes it after each call. Transcripts stay in memory for the current session. Linux requires `parec` on `PATH`; without it, microphone-only listening remains available. Restart listening after changing the default audio output.

## Security and platform limits

API keys are encrypted in the settings file and saving fails if the OS secure-storage backend is unavailable. The renderer never receives Node access directly, but it does receive settings through the preload bridge for editing. External source links are opened through a scheme-restricted main-process handler. CLI providers start without a shell and use temporary directories for image inputs.

The optional separate Aether ChatGPT login uses a `codex-profile` folder under Electron userData. Main resolves that location; the Codex child receives its own CODEX_HOME, explicit file/ChatGPT authentication and no inherited API/access-token variables. This does not change the parent or Claude login. Treat the profile's auth cache as a password. The checkbox selects that profile. `src/codex-login.js` handles sign-in: Settings → **Sign in to Codex** runs `codex login` for that CODEX_HOME with the browser suppressed, and main opens the printed OpenAI URL in a window with an in-memory session. Success is confirmed with `codex login status`, because `codex login` exits 0 even when cancelled. After sign-in the warm app-server is stopped so the next request loads the new token. Codex failures that look like a lost login (`refresh_token_invalidated`, 401, "log in again") are rewritten into a "Codex is signed out" message that points at the button. Free-account CLI eligibility and usage must be measured after successful sign-in rather than assumed from desktop access.

Current host selection is Codex CLI with that separate Free ChatGPT account, authenticated through the official device flow. Text and a controlled-image request passed, and the real packaged Settings UI saved/reloaded the selection with CLI-default models. Auto remains off; encrypted Tavily and local Whisper configuration are retained. Earlier Ollama setup below remains available for switching back. The account's limit endpoint currently exposes a 30-day primary window and displayed percent usage, not an exact task count or hours estimate; do not generalize this account's access/quota to every Free account.

Tavily is now configured on this Linux account. Real checks confirmed local-first library retrieval and live web fallback, with encrypted save/decrypt through GNOME Keyring. The user selected local Ollama: fast model `qwen25-vl-7b-16k:latest`, Smart model `qwen35-9b-64k:latest`, and the existing local Whisper model are configured. These installed aliases provide larger contexts for source packets. Tavily supplies evidence while Ollama writes the answer; source links and valid citation numbers still do not prove factual accuracy. This host's launcher explicitly selects GNOME Keyring so normal launches can decrypt the saved key.

Electron capture exclusion applies on macOS/Windows only and is best effort. Linux selected-window or tab sharing and full-window hide are the practical controls. Locked/proctored browsers may block the app. See [screen sharing compatibility](docs/screen-sharing.md).

## Extending the app

Linux placement belongs partly to the compositor. Native Hyprland ignored Electron's always-on-top hint for tiling, so `createWindow()` prepares the session rule before constructing the window. It matches only `dev.prahladv.aether`, survives app restarts in that compositor session, and needs Aether restarted after a compositor config reload. GNOME/KDE and other tiling managers need their own native verification; see README's desktop matrix.

When a drag ends, Aether joins the active workspace of the monitor under its center, so moving it to another screen keeps it bound to that screen's desktop. The current v3 Hyprland rule keeps Aether floating but unpinned, so it stays on its assigned workspace. It disables the older v1/v2 rules in the live compositor session before installing/reusing v3; an old pinned rule must not be silently reused after app restart. This Linux workspace behavior is separate from macOS's existing all-Spaces panel handling.

The full-width six-dot toolbar and bottom corners send narrow gesture events through preload. Hyprland updates use its actual cursor/window coordinates and target only the exact app process; repeated motion is coalesced rather than spawning an unbounded command queue. Release snapshots and flushes the final position, while cancellation and lifecycle cleanup stop motion. Other platforms use Electron's native drag region and bounded resize calculations. Opaque UI surfaces plus the Hyprland no-blur rule prevent the full transparent window from becoming a blurred square. Linux keeps mouse input enabled because ignored mousemove events cannot be forwarded back to the renderer.

Research buffers model output until citation validation succeeds. Sources appear immediately after retrieval and survive rejection or provider failure; a web retry replaces the local source panel. Numeric groups/ranges are checked outside formatted math/code. This validates reference IDs, not whether each claim follows from the cited passage. The retrieval date is not a publication date or proof that results are current; live Ollama replies still need factual-quality work.

Release verification separates renderer checks with a mocked Electron bridge from actual packaged startup and native desktop tests. An isolated user-data directory checks first-run defaults without changing existing settings; it does not reproduce a clean operating system, secure desktop keyring, or microphone/share permissions. Use the [release checklist](docs/release-validation.md) before claiming support for an environment.

- Add a model provider in `src/llm.js`, then add its selection and configuration fields in `renderer/` and defaults in `src/store.js`.
- Add or alter a task in `src/prompts.js`, then connect a UI action to its mode.
- Refresh the reference set with `node scripts/build-library.js`, inspect the content/license metadata, and run `npm test` and `npm run pack` so the package includes it.


Write mode humanisers (src/humanize.js): `createModelHumanizer` rewrites the whole text with the answer model; `createSentenceHumanizer` scores sentences with `aether_detect.py --segments` (via `detect.js segments()`), asks the model for 3 alternatives for only the most AI-like ones, and lets the detector choose. Chosen in Settings → Write (`writeMode.humanizer`: sentences (default) | model | local).
